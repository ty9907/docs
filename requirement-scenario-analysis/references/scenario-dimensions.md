# 三类场景维度库

生成场景清单前完整过一遍。目的不是把所有维度都用上，而是确保没有整类场景被漏掉。

输入为 spec / PRD 文档时，本文件负责补齐「spec 没写但会发生」的场景（标 `[Inferred]`）；spec 明写部分的抽取与来源标注规则见 `spec-ingestion.md`。

## 〇、分类判定规则

先按定义归到三类之一，再展开：

- **业务主场景**：正常业务动作，角色 / 对象状态 / 入口不同但路径正常。
- **边界场景**：值本身合法，但处在合法范围的边缘（临界值、临界时点、首末节点、刚好满一页）。
- **特殊场景**：同一份输入，因为存量数据、时序、并发、依赖、配置、入口不同而处在非典型处境。

判断口诀：**「值到边缘」归边界，「处境不同」归特殊**。并发、重试、历史数据、开关灰度一律归特殊，不归边界。

## A. 前置状态轴

### 数据态

- 空表 / 首次写入
- 已有同类数据
- 已有不同类或不同版本的数据
- 存在与本次输入冲突的数据（主键、唯一键、业务键相同）
- 存在软删、已作废、已归档的同键记录
- 存在脏数据：缺字段、非法枚举、历史遗留格式
- 跨期数据：补录历史日期、未来日期、跨账期、跨版本
- 数据量级：0 / 1 / 少量 / 大批量 / 达到分页或阈值上限

### 时序与状态机

- 首次操作 vs 第 N 次操作
- 前置流程已完成 / 未完成 / 被跳过
- 当前单据状态：草稿、进行中、已完结、已撤销、已锁定
- 操作发生在截止时点之前 / 之后 / 正好临界
- 顺序差异：先 A 后 B 与先 B 后 A 是否等价

### 环境与权限

- 操作者角色、数据权限范围、跨组织 / 跨租户
- 功能开关、灰度、配置项的开与关
- 依赖服务可用 / 降级 / 超时
- 多端入口：页面、接口、定时任务、导入、消息消费

## B. 输入轴

- 合法典型值
- 边界值：最小值、最大值、长度上限、精度、0、负数、临界时间戳
- 空值、null、字段缺省、空集合、空字符串
- 非法值：类型错误、枚举外取值、格式错误、越权引用
- 重复值：完全重复 / 同业务键但字段不同 / 格式差异重复（大小写、前后空格、时区、精度、全半角）
- 关联引用：外键存在 / 不存在 / 已软删 / 跨租户 / 循环引用
- 批量：单条、多条部分合法、超大批量、乱序、批次内含重复行

## C. 操作轴

- 新增 / 修改 / 删除 / 撤销 / 恢复
- 重试：同一请求再发一次，有无幂等键
- 并发：两个请求同时对同一业务键操作
- 批量 / 导入 / 断点续传
- 事务边界：单表、跨表、跨服务、最终一致
- 操作来源差异：用户手动 vs 系统自动 vs 定时任务补偿

## D. 结果与副作用轴：12 类关联影响面

对每个场景逐项核对，命中的写清具体变化。

1. **主表记录** — 新增 / 更新 / 不变、默认值、自增 ID、时间戳、版本号、软删标记
2. **关联表与外键** — 明细、快照、中间表、级联动作、孤儿数据
3. **唯一性与约束** — 主键、唯一索引、业务去重规则、乐观锁
4. **状态机与流程** — 是否触发流转、是否跳过前置节点、是否使已有单据失效
5. **统计与报表口径** — 计数、金额汇总、指标快照、T+1 报表、历史报表是否重算
6. **缓存与搜索索引** — 缓存失效、缓存穿透、索引同步延迟、列表排序变化
7. **消息与事件** — MQ、回调、站内通知、短信邮件、Webhook、订阅方重复消费
8. **外部与下游系统** — 同步 / 异步接口、对账文件、数据同步、第三方幂等
9. **权限与可见性** — 谁能看到新数据、数据权限边界、脱敏、越权
10. **审计与合规** — 操作日志、变更记录、留痕、数据保留策略
11. **性能与容量** — 锁竞争、慢查询、批量耗时、分页偏移、阈值告警
12. **历史数据兼容与迁移** — 老数据是否回填、字段默认值、版本兼容、回滚脚本、双写过渡

## E. 异常与恢复轴

- 失败点：校验前 / 写主表后 / 写关联表后 / 发消息后 / 回调下游时
- 部分成功：哪些已落库、哪些没有、对外表现是什么
- 事务回滚的完整性：消息、缓存、外部调用不会随数据库事务一起回滚
- 重试与幂等：重试后是否产生重复数据、重复通知
- 补偿、对账、人工修复路径
- 幂等键过期、并发竞争、死锁、超时后的状态不确定
- 撤销或回滚后，统计、缓存、通知、下游同步是否同步撤回

## F. 三类场景完整清单（核心）

### F1 · 业务主场景配额

逐项核对并展开命中的组合：

- 角色 / 权限：普通用户、管理员、运营、系统账号、访客
- 业务对象状态：草稿、进行中、已完结、已撤销、已锁定
- 动作：新增、修改、删除、查询、审批、导出、导入、批量
- 入口：页面、开放接口、定时任务、消息消费、文件导入、后台运维
- 数据来源：手工录入、系统生成、第三方同步、历史迁移
- 关联对象：有明细 / 无明细、有关联实体 / 无关联实体

### F2 · 边界场景配额（至少核对四组）

| 组 | 必须检查的取值 |
| --- | --- |
| 数值 / 集合边界 | 0、null、空集合、1 条、最小值、最大值、长度上限、精度末位、阈值、阈值±1、刚好一页 / 跨页、单次批量上限 |
| 时间边界 | 当天 00:00 与 23:59、月末 / 月初、跨天 / 跨月 / 跨账期、时区切换、有效期临界、截止时点前 / 后 / 正好相等 |
| 状态边界 | 流程首节点、末节点、最后一条、最后一个可操作位、刚好满足 / 差一点满足条件 |
| 首末次 | 第一次操作、最后一次操作、首次初始化、无历史数据、仅有一条历史数据 |

### F3 · 特殊场景配额（至少核对十组）

| 组 | 必须检查的取值 | 归类理由 |
| --- | --- | --- |
| 存量数据 | 无数据、老格式数据、脏数据、软删 / 已作废 / 已归档、跨期补录、字段缺失 | 处境不同 |
| 重复与重试 | 完全重复、同键不同值、格式差异重复、请求重发、消息重投、任务重跑 | 处境不同 |
| 并发与协同 | 两个请求同时、前台与定时任务重叠、多端同时操作 | 处境不同 |
| 时序 | 顺序颠倒、延迟到达、补录历史、先 B 后 A | 处境不同 |
| 部分失败与中断 | 批量中途失败、事务回滚、网络超时后续做、断点续传 | 处境不同 |
| 依赖异常 | 下游不可用、超时、降级、返回异常码 | 处境不同 |
| 权限差异 | 不同角色 / 租户、跨组织、数据归属变化 | 处境不同 |
| 撤销与回滚 | 操作后撤销、数据回滚、下游是否同步撤回 | 处境不同 |
| 配置差异 | 开关开 / 关、灰度命中 / 未命中、多租户配置不同 | 处境不同 |
| 多入口一致性 | 页面 / 接口 / 导入 / 定时任务 / 消息消费做同一件事，行为是否一致 | 处境不同 |

## G. 常见漏场景自检 16 条

输出前逐条打勾。

1. 只写正常路径，漏掉重复提交、重试、并发
2. 只看当前数据，漏掉历史数据兼容、补录、脏数据
3. 只看主表，漏掉关联表、快照、统计口径、报表
4. 忽略「无数据」本身是一种状态（空态展示、首次初始化、默认值）
5. 忽略软删、已作废、已归档记录被同键操作后「复活」
6. 忽略时序差异：先 A 后 B 不等于先 B 后 A
7. 忽略中途失败与部分成功
8. 忽略不同角色、租户、权限下同一操作结果不同
9. 忽略回滚后消息、缓存、下游数据未同步撤回
10. 把「重复数据」当成一种情况，未区分完全重复、同键不同值、格式差异重复
11. 忽略批量场景中的部分合法、乱序、批内重复
12. 忽略时间边界：跨天、跨月、跨账期、时区、临界时点
13. 忽略对已生成的历史报表和已发出通知的追溯影响
14. 用「应报错」代替完整结论，缺错误表现、数据状态、恢复方式
15. 把维度库补出的场景写成 spec 明写，未标 `[Inferred]` 与具体维度组
16. spec 声明由公共组件处理 / 不在范围的场景被静默省略，未进 Scope Reduction Log

## H. 每条场景的「代码检查线索」写法

线索必须让另一个人（或下一阶段的检索）能直接去代码里找，格式：

`应当出现：<判断/分支/守卫/默认值/兜底> ｜ 可检索：<关键词1>、<关键词2>`

示例：

- 边界场景「消费额刚好等于阈值」→ `应当出现：阈值比较分支且含等号 ｜ 可检索：阈值常量名、>=、compareTo`
- 特殊场景「任务重跑」→ `应当出现：幂等键或执行记录判重 ｜ 可检索：idempotent、幂等键字段、job_log、唯一索引`
- 特殊场景「开关关闭」→ `应当出现：开关判断且关闭分支等价旧行为 ｜ 可检索：feature flag 名、配置 key`

禁止写「注意判空」「需考虑并发」这类无法检索的线索。

## I. 来源标注与排除留痕（配合 spec-ingestion.md）

每条场景的「来源」列只有三种合法写法：

| 标注 | 何时用 | 示例 |
| --- | --- | --- |
| `[Source]` | spec 明写，可定位到章节 / 编号 | `[Source] spec §3.2 / AC-07` |
| `[Source+Derived]` | spec 给了规则，取值由本 skill 派生 | `[Source+Derived] spec §4 阈值 100 → 派生 99/100/101` |
| `[Inferred]` | spec 未写，由本文件 F1 / F2 / F3 补齐 | `[Inferred] F3-重复与重试` |

- `[Inferred]` 必须指到具体组，便于反查「为什么补这条」。
- spec 明写但缺关键定义时，在标注后补 `【未提供】`，例如 `[Inferred] F2-时间边界；spec 未定义跨账期口径【未提供】`。
- 纯需求描述路径下全部标 `[Inferred]`（或 `[Source] 用户口述`），同样不许留空。
- **只有 spec 明确声明**（由公共组件处理 / 不在范围 / 沿用现有逻辑）才可排除某组场景，且必须写进 Scope Reduction Log 并附 spec 原文依据；排除后仍保留一条核对项，确认该能力在新的入口 / 数据态下确实生效。详细规则见 `spec-ingestion.md` 第四节。
